# v1 Project Cognition Threat Model

## Assets

- canonical project binding and repository evidence
- bitemporal claims, checkpoints, work state, observations, and decision history
- local media sources and derived descriptors
- cognition responses, receipts, and public-safe exports

## Trust Boundaries

- repository and media bytes are untrusted input
- thread/capture records are unverified historical evidence
- operator verification can raise authority only through explicit provenance-bearing actions
- CLI and MCP hosts are trusted local callers within their configured capabilities
- the browser is loopback-only and capability-authenticated

## Principal Threats And Controls

| Threat | Control |
| --- | --- |
| Wrong checkout or database | canonical root, repository, and checkout identity revalidation |
| Stale index presented as current truth | indexed-snapshot labeling plus explicit live/deep freshness gate |
| Bounded output presented as complete | exact totals, displayed counts, omitted counts, and truncation flags |
| Low-trust text promoted into fact | pramana, verification status, authority weighting, and abstention |
| Malicious or substituted media path | canonical confinement, link/reparse/hard-link rejection, stable descriptor and digest checks |
| Derived media description treated as source | separate source/derivation records and operator-only verification |
| Private media or paths exported | metadata-only public export and path redaction |
| Oversized cognition denial of service | fixed input/output/list budgets and fail-closed projection limits |
| Agent gains execution authority | read-only cognition layer; no tool execution, model routing, or repository mutation |

## Residual Risk

Same-user malware or administrator/root access can read local files. Deterministic
reconciliation cannot prove an external service completed or a human judgment is
correct. Approximate code edges can miss dynamic behavior. Secret scanning and
redaction are defense in depth, not proof against every unknown secret format.
