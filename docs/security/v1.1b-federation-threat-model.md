# v1.1B Governed Federation Threat Model

Status: implementation threat model  
Design: `docs/superpowers/specs/2026-09-07-v1.1b-governed-federation-design.md`

## Protected Assets

- private project memories, evidence, comments, approvals, and provenance;
- valid-time and transaction-time history;
- device signing and envelope private keys;
- scope content keys and passphrases;
- peer capability and revocation history;
- local brain availability, integrity, and recoverability;
- the operator's deliberate sharing and conflict decisions.

## Trust Boundaries

1. Operator to local CLI, MCP, and dashboard action preview.
2. Local process to protected identity-key files.
3. Local brain to imported encrypted event envelope.
4. Peer to peer across an untrusted transport.
5. Client to optional self-hosted relay.
6. Federation projection to local search, context, and diagnostic surfaces.
7. Exported review bundle to an explicitly named audience and privacy ceiling.

## Adversaries

- a malicious or compromised relay;
- a revoked, suspended, or over-curious peer;
- a compromised authorized device;
- an attacker replaying, truncating, reordering, duplicating, or replacing
  envelopes;
- a local unprivileged account attempting to read another account's files;
- untrusted repository or transcript content attempting prompt or parser abuse;
- an honest operator using the wrong key, brain, scope, or recovery artifact.

Mutually untrusted processes under the same OS account are not isolated by the
file-permission model and require a separate account or machine boundary.

## Security Properties

- Relay confidentiality: no plaintext project data or plaintext scope keys.
- End-to-end integrity: event digest, author signature, and AEAD verification.
- Authorship: a valid signature proves possession of a device key, not a human
  identity.
- Causal integrity: parent references and per-author sequence are validated.
- Replay safety: accepted event IDs and author sequence positions are unique.
- Least disclosure: content is encrypted under the narrowest selected scope.
- Revocation: removed peers do not receive keys for later scope epochs.
- Local sovereignty: the relay cannot authorize, resolve, or delete local truth.
- Recoverability: interrupted mutation either rolls back or exposes an explicit
  incomplete recovery state.

## Threats And Required Controls

| Threat | Required control | Failure behavior |
| --- | --- | --- |
| Relay reads content | AEAD ciphertext and HPKE key envelopes only | No plaintext fallback |
| Relay swaps or edits bytes | SHA-256 content address, Ed25519 signature, AEAD tag | Quarantine as tampered |
| Relay withholds history | Parent closure, cursor reconciliation, explicit partial-sync state | Never claim complete |
| Replay or duplicate | Event-ID and author-sequence uniqueness | Idempotent duplicate or quarantine conflict |
| Event under wrong space/scope | Domain-separated canonical signature and AEAD associated data | Reject before decrypt/project |
| Unauthorized author | Capability evaluation at causal frontier | Quarantine before indexing |
| Revoked peer sends backdated event | Signed sequence, causal capability interval, revocation frontier | Quarantine or explicit concurrent-governance conflict |
| Concurrent admin revocation | No last-writer-wins; retain both events | Block sensitive projection pending owner decision |
| Scope key reuse after revocation | Atomic epoch increment and fresh random content key for every affected scope | Revocation rolls back if any required rotation fails |
| Lost or copied private key | Passphrase-protected PKCS8, owner-only files, replacement/revocation workflow | Honest device-compromise state |
| Wrong passphrase or missing key | No recovery bypass or destructive regeneration | Key-missing/recovery-required |
| Nonce reuse | Random 96-bit nonce plus uniqueness test per scope epoch | Refuse duplicate nonce |
| Ciphertext size bomb | Encoded/decoded size, nesting, count, and time ceilings | Reject without partial projection |
| Malformed canonical JSON | Strict schema, duplicate-key rejection, bounded parser | Reject before cryptography |
| Cross-project or cross-scope recall | Project and scope authorization before query and expansion | Omit with non-sensitive reason |
| Diagnostic leakage | Aggregate counts and opaque IDs; no unauthorized content or local paths | Redacted diagnostic |
| Export over-sharing | Preview, exact audience, privacy ceiling, include manifest, redaction proof | No output without confirmation digest |
| Downgrade | Wire and database version checks in signed context | Refuse with upgrade guidance |
| Rollback illusion | Step journal records every mutation and restoration result | Report incomplete rollback |

## Revocation Limits

Revocation rotates future scope keys and rejects later unauthorized events. It
cannot erase plaintext, screenshots, exports, backups, or keys already copied
by an authorized peer. Historical events remain decryptable to peers that
legitimately received the historical epoch key. Product copy and operator UX
must state this before revocation confirmation.

The optional relay capability is space-wide transport authorization, not a
peer identity credential. A revoked peer that retained it may still enumerate
and download opaque relay envelopes until the operator rotates that transport
capability. Atomic scope-key rotation prevents that peer from decrypting later
epochs, but does not conceal traffic metadata or revoke access to historical
ciphertext. Deployments needing immediate transport exclusion must rotate the
relay capability independently.

## Metadata Leakage

An untrusted relay may observe opaque space and scope IDs, peer-key
fingerprints, envelope size, access timing, traffic volume, and epoch changes.
Padding and anonymous routing are not v1.1B properties. Project names, memory
types, object IDs, comments, decisions, repository paths, and content remain
inside ciphertext.

## Verification Matrix

Required automated and operator tests:

- known-answer HPKE, Ed25519, and ChaCha20-Poly1305 tests;
- wrong key, wrong associated data, modified header, modified ciphertext, and
  modified signature rejection;
- duplicate event, duplicate sequence, duplicate nonce, replay, missing parent,
  cyclic parent, oversized envelope, and event-count exhaustion;
- offline divergent peers converging without erasing contradictory claims;
- grant, revoke, rotate, suspend, re-admit, and lost-device replacement;
- revoked peer denied new epochs while prior-plaintext limitation remains
  visible;
- revocation atomically rotates every affected scope and excludes the revoked
  peer from all new key envelopes;
- partial relay history, outage, stale cursor, corrupted cursor, and recovery;
- authorization checks before all six required product surfaces;
- schema v11 inspection, approved v12 migration, interruption, rollback,
  newer-runtime refusal, and local-only operation after federation removal;
- synthetic novice, maintainer, security-reviewer, and offline dashboard flows;
- repository, wheel, binary, SBOM, screenshot, and website privacy scans.

## Deferred Risks

- Human identity verification and enterprise directory binding.
- Traffic-analysis resistance and length-hiding padding.
- Hardware-backed keys and mutually untrusted same-account processes.
- MLS-compatible forward secrecy and post-compromise security.
- Multi-admin consensus beyond explicit conflict blocking and owner resolution.

Deferred risks must remain visible in release notes and must not be described as
implemented protections.
