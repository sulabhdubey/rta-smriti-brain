# v1.1B Governed Federation Implementation Plan

Design: `docs/superpowers/specs/2026-09-07-v1.1b-governed-federation-design.md`  
Threat model: `docs/security/v1.1b-federation-threat-model.md`  
Baseline: `docs/V1_1_CAPABILITY_BASELINE.md`

## Execution Rules

- Use failing test, smallest fix, focused verification for every slice.
- Work only in the isolated `feature/v1.1b-governed-federation` worktree.
- Use synthetic Atlas-style projects, opaque peer IDs, and generated keys.
- Never commit local brains, key files, passphrases, receipts, support bundles,
  transcripts, machine paths, or private project evidence.
- Do not commit, push, merge, tag, publish, deploy, or contact anyone without a
  fresh exact approval gate.
- Keep federation optional. Local-only behavior and budgets must remain intact.
- A test passing locally is evidence for that test, not release completion.

## Slice 0: Baseline Contract

- [x] Reconcile the v1.1A capability and native-host evidence matrix.
- [x] Freeze benchmark, performance, privacy, and recovery evidence.
- [x] Record architecture alternatives, selected protocol, threat model,
  performance budgets, and non-goals.
- [x] Add a machine-readable baseline manifest and a regression test that
  rejects missing evidence labels or broadened host claims.

Exit: docs and manifest agree on source commit, versions, commands, results,
limitations, and pending external evidence.

## Slice 1: Schema v12 And Immutable Store

- [x] Write migration tests for v11 inspect-only, approved v12 migration,
  interruption rollback, v11 downgrade refusal, and local-only recovery.
- [x] Add federation tables, constraints, triggers, and indexes.
- [x] Implement bounded canonical JSON with duplicate-key rejection.
- [x] Implement immutable event insert, idempotent duplicate, tamper collision,
  pending-parent, quarantine, and projection-state APIs.
- [x] Add 10,000-event storage and deterministic-order probes.

Exit: two local databases can store the same synthetic event set and derive the
same validated order without decrypting or projecting content.

## Slice 2: Identity And Cryptographic Envelopes

- [x] Write known-answer and negative tests before crypto implementation.
- [x] Generate passphrase-protected Ed25519 and X25519 private identity files.
- [x] Add public fingerprints, key import/export, backup, inspect, and device
  replacement primitives.
- [x] Seal scope keys to peers with the documented X25519/HKDF/AEAD envelope
  construction and encrypt events with
  ChaCha20-Poly1305.
- [x] Bind protocol version, space, scope, epoch, author, sequence, parents,
  nonce, and ciphertext through canonical signing and associated data.
- [x] Test wrong keys, wrong scope, wrong epoch, nonce duplication, tampering,
  replay, and bounded malformed inputs.

Exit: a relay-visible envelope reveals no synthetic payload fields and only an
authorized peer can verify and decrypt it.

## Slice 3: Capability Ledger And Protection Scopes

- [x] Write authorization-frontier tests for owner, maintainer, reviewer,
  reader, suspended, revoked, and unknown peers.
- [x] Implement local, team, review, and custom scopes.
- [x] Implement append-only grants, suspensions, revocations, rotations, and
  re-admission.
- [x] Enforce scope capability before ingest/projection, retrieval, context,
  outbound sync, export, and diagnostics.
- [x] Add concurrent incompatible admin-change conflicts with explicit owner
  resolution; never last-writer-wins.

Exit: revoked peers cannot decrypt new epochs or inject newly unauthorized
events, and the prior-plaintext limitation is present in API and UX output.

## Slice 4: Domain Projection And Collaboration

- [x] Write divergent-offline tests for assertions, corrections, evidence,
  comments, review requests, approval proposals, and decisions.
- [x] Project accepted federation events into provenance-linked local memories
  and bitemporal truth without replacing source events.
- [x] Preserve concurrent contradiction, attribution, valid time, transaction
  time, abstention, and unresolved disagreement.
- [x] Add immutable comment and approval history plus explicit acceptance or
  rejection receipts.
- [x] Add selective promotion from quarantine with operator authority.

Exit: two peers converge on the same event set and projections while material
disagreement remains visible and unresolved until an explicit decision.

## Slice 5: Transport And Offline Sync

- [x] Define transport conformance tests.
- [x] Implement bounded content-addressed filesystem relay.
- [x] Implement digest inventory, missing-event exchange, pull/push preview,
  resumable cursors, verification, and repair.
- [x] Test outage, truncation, reordering, duplication, stale cursor, corrupted
  cursor, missing parent, partial history, and interrupted transfer.
- [x] Implement optional loopback/self-hosted HTTP relay only after the
  filesystem transport passes; retain identical opaque-blob semantics.
- [x] Add relay quotas, rate limits, bounded reads, atomic no-clobber writes,
  health response, and no-content logging.

Exit: the same two-brain scenario passes through both enabled transports, and
relay inspection finds no plaintext fixture content.

## Slice 6: Signed And Encrypted Review Bundles

- [x] Extend review bundles with author signature, recipient HPKE envelope,
  exact scope/audience manifest, privacy ceiling, evidence inclusion manifest,
  redaction proof, and excluded-content proof.
- [x] Preview and digest-bind every export and import.
- [x] Preserve non-authoritative summary labeling and original source-event
  provenance.
- [x] Test wrong audience, revoked recipient, modified manifest, modified
  ciphertext, partial archive, oversized archive, and recovery.

Exit: a recipient can verify authorship, integrity, audience, redactions, and
included evidence without learning excluded content.
